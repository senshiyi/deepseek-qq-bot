# 群消息与表情包使用说明

当前阶段处理群文字、表情包和白名单私聊。语音按用户要求暂停，运行以下命令不会采集、播放或恢复语音。用户已选择**主动观察群聊、适当插话及发表情包**，当前本地配置为 `active`。

## 已能做什么

- 手动发送文字、QQ内置表情、清单中的图片/GIF表情包；默认只预览，明确 `--live true` 才发送。
- 接收普通账号的群消息，并接收私聊白名单联系人的消息；每个群和联系人分别保存最近20条/4000字符上下文，10分钟过期。模型只决定正文与表情ID，不能改变收件目标、执行API或读取文件。
- 白名单私聊无需@，每位联系人独立限频为至少8秒、每小时最多30次；私聊与群消息不共享上下文、冷却或小时计数。
- 私聊忙碌或8秒冷却内的新消息会暂存，当前回复完成且冷却满足后合并处理下一轮。每位联系人待处理最多20条/4000字符、2分钟过期，暂停清空；达到小时上限不堆到下一小时。
- 结构化@或名字开头的明确点名，至少间隔8秒、每小时最多30次；active模式也使用这套直接对话限制。
- 未点名的主动插话至少间隔120秒，每小时最多6次评估机会；模型可 `send=false`，这次仍占评估次数。两路小时计数独立，间隔从最近任一路预留起算，防止跨路连续刷屏。
- **群里按触发者取人格**：白名单联系人发言触发回复时，用他自己的专属人格（称呼、性格、说话风格）；其他群成员发言仍用全局角色。角色页关掉"群聊沿用角色"时一律回全局。回复字数上限和表情概率这类数值设置仍沿用全局，避免单人设置影响整个群。
- 群聊的`mention`只响应@/名字；`manual`关闭自动触发。群聊忙碌或冷却时只收上下文，不排队补发旧消息；本地显示 `message_skipped` 及原因，不刷提示。
- **明确@了别人的消息不插话**：消息里的@指向另一位成员（不是本账号）时，即使 `active` 也不会主动参与，拒绝原因记 `addressed_elsewhere`，也不消耗主动参与的评估名额；@全体成员仍当作可能与本机相关。@本账号或名字点名照常直接回答。
- **正文里出现库内表情 ID 会自动补发那张**：模型偶尔把 `qq_face_66`、`miku_02`、`self-xxxx` 直接写进正文（没填 `memeId`）。解析时会找到第一个带下划线/连字符的库内 ID，把正文里的它清掉、并把它当作 `memeId` 一起发出去；已经显式给了 `memeId` 时以显式为准（正文里的 ID 只清不发）。普通英文单词（不带下划线/连字符的 ID）不受影响。
- **群里插话会引用那条消息**：`active` 主动接话时，发送的消息第一个段是 OneBot `reply`（引用触发它的那条消息），别人一眼能看出在答谁；@本账号或名字点名的直接回复不加引用。`reply` 段只允许出现在最前面、每条消息最多一个、id 必须是 1～19 位数字（可带负号），否则发送前就拒绝。真实 QQ 已验证：NapCat 接受引用一条二十多分钟前的群消息并返回 message_id。
- 自身消息、重复事件、过期事件、错误账号及未授权群/联系人被过滤。暂停和超时使旧结果失效，恢复不续发旧回复。

当前授权群保存在忽略的 `group-chat.local.json`，机器人账号由用户指定为1667533356。不要用公共示例覆盖已有本地配置或 `.env`。主动文字与“好耶”图已经过该群另一账号确认可见，详见 [验证记录](group-messaging-results.md)。QQ连接由NapCat保持，AI回复由群聊程序负责，持续响应需要两者同时运行。

频率与对话上下文按本次运行会话统计，历史只在内存保存，重启会重置；累计费用账本跨运行保留。当前本地默认引擎为学校 `school`，已按用户本轮授权取消学校累计点数/请求次数上限，继续真实计费；原DeepSeek直连额度仍0.30元/10次。两份账本独立，均为保守预留而非实际账单。不要删除或重置账本。学校配置与恢复步骤见 [学校API说明](school-api-guide.md)。

## NapCat账号接入

独立包已准备于 `Cache/NapCat/v4.18.38`，官方SHA256已核对。不修改 `E:\QQ` 的程序文件，但无法保证账号数据与桌面QQ完全隔离。用户已选择让机器人账号退出桌面，再交给NapCat；其他桌面QQ保留。

在专用 PowerShell 窗口启动：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\Files\Start-NapCat.ps1 -Qq 1667533356
```

脚本先准备127.0.0.1的WebUI、API与事件配置，账号登录由你扫码/确认。它会备份将修改的本地配置、保留原DeepSeek密钥、匹配已有selfId；发现其他已启用适配器则拒绝自动启动。`-PrepareOnly`只准备配置。不会运行包内的 `KillQQ.bat`。关闭QQ主窗口不一定退出登录；若扫码提示“当前账号已登录”，从托盘退出机器人账号的桌面会话，保留手机QQ用于扫码，不删除登录数据库。

本机遇到过WebUI已打开但没有二维码：SDK的connect返回成功，却没有连接完成回调。已按用户明确授权提供可选补救；**当前NapCat保持登录时不要再次运行启动命令**。下次确实需要重新启动，且确认原实例已停止后，可用：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\Files\Start-NapCat.ps1 -Qq 1667533356 -LoginFallback
```

它核对固定v4.18.38源码及入口的SHA256，仅生成副本；5秒后只有原生连接成功、未初始化、没有二维码或登录错误且状态与本次实测相符时，补走原登录初始化。同一连接周期只认领一次，防止晚到回调再次刷码；正常断开后允许新周期。补救仍需正常扫码/确认，不会绕过QQ认证。去掉 `-LoginFallback` 即回到官方入口，原发行文件始终保留。若源码升级或副本已有不同内容，拒绝覆盖。

补救通过了20项离线VM和15项隔离准备/防重检查。后续用户关闭NapCat后，已用正式 `-LoginFallback` 参数重新启动并通过缓存登录恢复账号；长时间断线恢复仍待验证。脚本会在写配置前拒绝重复启动本项目的Node，不结束其他QQ/Node进程。NapCat已登录时，直接运行群聊只需下文 `chat` 命令。

该补救的去重覆盖连接回调入口，保留官方快捷/密码登录实现；离线测试没有证明这些第三方异步回调在断线后迟到时也能丢弃旧结果。遇到快捷登录中途断线或二维码再次变化，应核对当前码和账号，必要时停止本实例后重新启动，不以本次测试声称已具备长时自动恢复能力。

本机端口分别为：WebUI **6099**、发送API **3000**、群事件入口 **17801/onebot/**。OneBot Token在忽略的 `.env`，WebUI使用另一份随机口令；不要分享带Token的链接或完整登录日志。完整依据及恢复方法见 [napcat-messaging-setup.md](napcat-messaging-setup.md)。

登录后先检查：

```powershell
.\start.cmd chat-check
```

它只查询登录状态和本地配置，不发消息。`selfId`必须与配置一致。每次真实发送前也会复核账号；若NapCat重新登录或切换账号，应停止并重启本项目群聊。OneBot没有提供“检查账号与发送”原子绑定，复核不能代替稳定的单账号服务。

`chat-check`还显示本地默认的 `engine/model/apiBaseUrl/keyEnvironment`，其中 `engineScope` 明确标记这是配置值。显式 `--engine` 可以覆盖该默认值，因此确认**正在运行的程序**实际走哪个入口，应在聊天窗口按 **S**，查看状态中的相同字段；启动时的 `started` 也会显示实际选择：

| 引擎 | 模型 | API根地址 | 密钥环境变量名 |
| --- | --- | --- | --- |
| `school` | `deepseek-v4-flash` | `https://myai.bupt.edu.cn/llm-gw/v1/` | `SCHOOL_API_KEY` |
| `deepseek` | `deepseek-flash` | `https://api.deepseek.com/` | `DEEPSEEK_API_KEY` |

这里只显示变量名，不显示密钥值。`school-check`只检查学校配置和账本，不能证明当前聊天程序使用学校引擎；模型回复中自称的身份或来源也不能替代实际运行状态。

## 先预览，再发送

```powershell
.\start.cmd memes
.\start.cmd chat-send --group "授权群号" --text "文字与表情包发送测试" --meme roger
```

以上不会连接发送接口。确认后才在已同意的群和时段使用：

```powershell
.\start.cmd chat-send --group "授权群号" --text "文字与表情包发送测试" --meme roger --live true
.\start.cmd chat-send --group "授权群号" --face 14 --live true
```

`face`为QQ内置表情ID，需NapCat支持该ID。发送成功回执表示OneBot接受，不等于对端显示已被验证；首次应在群里核对文字、图片和GIF动效。超时或取消发生在提交后时，可能已投递，**不要自动重发**，先查看群记录。

## 自动群聊与白名单私聊

长期运行可双击项目根目录 `start-chat.cmd`。它读取本地配置中的机器人账号、唯一授权群和私聊白名单，先检查登录，再开启群与私聊共用的聊天程序；NapCat没有运行时打开专用登录窗口，扫码/确认仍由你完成。已有聊天接收端运行时拒绝重复启动，不会结束现有进程。

也可在NapCat已登录时直接运行：

```powershell
.\start.cmd chat --group 1095601728 --mode active --live true --seconds 0
```

`--seconds 0`没有自动结束时间，按Q/Ctrl+C停止。保持两个窗口运行即可，窗口可最小化；关闭NapCat会断开QQ连接，关闭聊天窗口会停止群与私聊的AI处理。电脑关机、休眠、网络断开或QQ离线会影响响应；入口不设置Windows服务、开机自启或更改电源设置。

私聊配置保存在忽略的 `group-chat.local.json`，本机仅开放用户QQ **29070481**：

```json
{
  "allowedPrivateUserIds": ["29070481"],
  "privateIntervalSeconds": 8,
  "privatePerHour": 30
}
```

以上是需保留其他字段的配置片段，不要用它覆盖整个本地文件。公共模板的 `allowedPrivateUserIds` 默认为空列表，表示关闭私聊；从白名单移除联系人后停止聊天程序并重新启动使配置生效。白名单联系人向QQ1667533356直接发文字即可，不需@或机器人名字。私聊只带本联系人上下文，不附带群聊天或群图片；学校入口尚无读图能力。验证应由联系人自行发起私聊，不能把OneBot发送回执当作对端可见确认。

快速连发可以分条补充同一个问题；忙碌或冷却中的补充会合并到下一轮，不会为每条分别生成回复。如果合并的那几句是在她已经回过一句之后才轮到的，提示词会明确指出"这条你已经回过一次了"，默认可 send=false 不再复读同一件事，要回也只回半句并保持上一条的语气。待处理区与10分钟有效的对话历史不同，只保留2分钟；S状态中的 `PendingMessages` 显示当前待处理消息数。按P暂停或X取消并暂停会清空待处理消息，恢复后不会补发旧问题；达到每小时30次时也不会一直积压等下一小时。

```powershell
# 不调用模型、不实际发群，只用固定回复验证事件触发
.\start.cmd chat --group "授权群号" --mode active --seconds 600

# AI预览：会发送文本上下文及明确关联的图片给DeepSeek，计入预算，不发群
.\start.cmd chat --group "授权群号" --mode active --engine deepseek --seconds 600

# 实际自主群聊：模型决定是否插话及选表情
.\start.cmd chat --group "授权群号" --mode active --live true --seconds 600
```

直接使用chat命令时默认会话600秒；正数允许10～86400秒，到期退出；0表示持续运行。**P**暂停/恢复、**X**暂停并取消当前生成、**S**状态、**Q/Ctrl+C**退出，统一作用于群与私聊。暂停前已经提交给QQ的请求可能已送达，无法通过本地取消保证撤回；后续旧结果不会再提交。

学校初期的0.10点/10次仅适用于上一测试阶段；用户本轮已取消学校累计上限，本机 `maxPoints` 与 `maxCalls` 均设为显式 `null`，不再因旧账本达到10次而停止调用。原账本继续累计，学校平台仍按用量计费。单请求256输出Token/25秒限制不变。旧的有限学校配置仍可使用，达到任一上限后停止新调用。DeepSeek直连仍为0.30元/10次，不自动切换引擎。

主动模式先过滤纯图片/表情摘要和极短噪声，再在限流允许时将有内容的聊天、问句或情绪反应交给模型。它不是定时刷消息，也不会每条都回复。模型可只发一张表情，也可只发文字；目前一次最多一张。受限频率只在本次运行内计数，重启会重置消息冷却；DeepSeek费用账本独立持久保存，不随重启重置。

## 表情包库

默认库为 `Files/Memes`，已有三张原创反应图：

| ID | 用途 |
| --- | --- |
| `roger` | 收到、确认、明白 |
| `yay` | 开心、庆祝、赞同 |
| `thinking` | 思考、等等、疑问 |

添加自己的素材时明确指定本机文件完整路径：

```powershell
.\start.cmd meme-import --id "happy-cat" --file "E:\MyPictures\happy-cat.gif" --tags "开心,庆祝,猫"
.\start.cmd memes
.\start.cmd chat-send --group "授权群号" --meme happy-cat
```

支持PNG/JPEG/GIF/WebP，单次图片原始总量最多5MiB；导入复制原始文件，不修改或删除来源，不覆盖已有ID。清单不接受任意路径、URL、目录联接或符号链接逃逸。并发导入使用跨进程锁，超时不写新素材。模型不能自行导入文件。

GIF/WebP原始字节可以作为图片提交；实际动画、接收端压缩和原生收藏表情外观仍须实发验证。第一版不冒充商城 `mface`，也不假设账号拥有付费表情资格。模型启动时读取表情清单，新增表情后重启群聊会话使标签进入选择范围。

## DeepSeek与预算

原DeepSeek直连仍使用本地 `.env` 的 `DEEPSEEK_API_KEY`、`deepseek-flash`，可显式选 `--engine deepseek`。当前学校引擎使用独立的 `SCHOOL_API_KEY` 与 `deepseek-v4-flash`，见 [学校API说明](school-api-guide.md)。只在决策完整且通过校验后发送，不发送半段JSON或推理字段。授权群和白名单私聊各自的文字上下文发往所选服务，语音保持暂停。

DeepSeek 的累计金额与调用次数默认 **0.30 元／10 次**，现在可以在面板“运行设置 → 模型预算”里调（金额 0.01～100 元、次数 1～1000 次），保存并应用后生效；账本仍是 `Results/local/deepseek-budget.json`。新文本功能与原语音入口共用跨进程保护的预算，调用前重读并预留，不自动退款或重置；账本是保守费用预留，非官方账单。达到上限停止新的模型调用，手动发送和固定预览不产生模型费用。

开发用正式模型选择检查：

```powershell
.\start.cmd chat-ai-check
```

此命令会计入预算，但不发QQ。此前实际返回 `send=true`、正文“已收到”、表情ID `roger`，该次后累计预留0.024718元、调用2次；后续真实群主动回复测试后累计为0.037556元、3次。实际账单以DeepSeek控制台为准。
