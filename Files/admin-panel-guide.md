# 本地管理面板使用说明

这份说明对应当前项目的消息宿主和本地面板，涵盖群文字、表情包与白名单私聊。**语音仍暂停**，以下操作不会开始采集、播放或加入 QQ 通话。这里描述已实现的操作方式，不表示新面板已经完成真实 QQ 联调验收。

## 1. 启动与连接

1. 在项目根目录运行 `start-chat.cmd`。它读取现有 `group-chat.local.json`，编译检查入口，并核对 NapCat 登录账号；NapCat 必须在线并登录配置的机器人账号。
2. 若本项目 NapCat 尚未启动，入口会打开专用登录窗口。扫码、设备确认等验证需要你手动完成，最长等待 180 秒；已有实例不会被强制重启。
3. 等聊天窗口显示消息服务和本地管理地址后，运行根目录的 `open-panel.cmd`。
4. 浏览器会打开[正式本机面板](http://127.0.0.1:17802/)并自动连接。先查看“概览”中的实际引擎、当前群及运行状态，再进行修改。

`open-panel.cmd` 从 `Results/local/admin-access-token.txt` 读取本机管理令牌，通过浏览器地址片段交给页面；页面读取后会移除地址中的令牌。脚本和启动窗口不会打印令牌，页面仅在当前浏览器会话中保存它。不要分享带令牌的链接、令牌文件或包含私聊资料的管理页截图。

正式面板只监听本机 `127.0.0.1:17802`。不要用其他测试端口的临时页面判断正式宿主是否运行，也不需要把管理端口开放到网络。

保持 **NapCat 与聊天消息宿主** 同时运行，浏览器可随时关闭。关闭网页或“退出连接”只结束页面连接，**不会停止机器人**；再次运行 `open-panel.cmd` 即可回来。

要关闭控制台后继续运行，双击根目录 `start-chat-background.cmd`。它会复用已运行的本项目宿主，未运行时才隐藏启动；不会反复创建占用17801的新进程。电脑仍须开机且不休眠，没有设置开机自启，也没有修改睡眠策略。账号资料可读不代表QQ在线，入口和概览现在分别核对QQ状态及账号；最终收发仍以实际回复为准。

## 2. 暂停、恢复与停止

面板“概览”中的暂停、恢复同时作用于当前群和白名单私聊。暂停会取消尚未完成的回复并清空待处理私聊；恢复不会补发这些旧消息。已提交给 QQ 的请求可能已经送达，暂停不能保证撤回。

聊天运行窗口也保留以下按键：

| 操作 | 效果 |
| --- | --- |
| `P` | 暂停或恢复群聊与私聊回复 |
| `X` | 暂停并取消当前回复，清空待处理消息 |
| `S` | 立即显示实际引擎、模型、接口、状态和预算预留 |
| `Q` | 退出整个消息宿主，同时关闭本地管理服务 |

面板“停止机器人”同样结束整个消息宿主和管理服务，之后页面连接会断开；它不是只关网页，也不会顺带关闭独立的 NapCat 登录窗口。重新运行 `start-chat.cmd`，再运行 `open-panel.cmd` 才能恢复。

## 3. 修改角色

角色设定保存在项目根目录的 `bot-profile.local.json`。没有该文件时使用默认角色：名字“乖乖”、性格“友好、坦诚，尊重事实”、称呼“你”、风格“自然中文，简洁完整”、回复上限 160 字、表情允许发送比例 100%。**当前版本不会自动替你改成女儿角色。**

| 字段 | 允许范围 | 生效范围 |
| --- | --- | --- |
| 角色名字 | 1～16 字 | 群聊与私聊共用，也加入本次运行的名字识别 |
| 对用户的称呼 | 1～32 字 | 私聊；群角色开启后，须由当前QQ的笔记或公开偏好确认相应关系 |
| 性格与人设 | 1～2000 字 | 私聊；可开关群聊使用 |
| 说话风格 | 1～1000 字 | 私聊；可开关群聊使用 |
| 回复字数上限 | 40～3000 的整数 | 群聊与私聊共用 |
| 表情允许发送比例 | 0～100 的整数 | 群聊与私聊共用 |

回复字数是允许的**最大长度**，不是要求每次写满。即使设为 3000，简单问题仍可简短回答；较高上限允许更长回复，也可能增加模型用量。可设置范围调整不会自动改变你已经保存的角色上限，实际仍以面板中的已保存值为准。

这些字段不能只填空白。**角色设定是一套全局设定，并非每个联系人独立一套。** “群聊使用角色设定”决定群聊是否采用性格和风格；关系称呼仍绑定当前发言者的QQ，不把某联系人的家庭关系套到其他人。不要把秘密写进全局角色。

“群聊共享当前联系人的长期笔记”开启后，授权群里会自动读取当前明确触发回复的QQ对应笔记。不会读取该联系人的私聊原文，也不会根据自称、昵称、转述或@对象换人取笔记。关闭此开关可恢复群聊仅用人工批准公开偏好的行为。**把笔记交给模型后，无法硬保证模型不复述；不要共享必须保密的笔记。** 两项开关保存后须应用设置。

角色页的“从历史生成角色草稿”只在你点击后调用当前运行的文字模型。选择白名单联系人，提取该QQ近7天、最多40条且序列化后最多12000字符的历史；原文将发送给当前模型服务并计入原账本。提取对象是机器人的性格和相处方式，不是用户人格。生成不会修改角色；检查并编辑四个建议字段后，明确确认保存，再应用设置。草稿30分钟失效、宿主重启丢弃；生成后若角色已手动改过，确认会拒绝覆盖。主表未保存修改先自行保存或复制，避免相互覆盖。模型可能提取不准确或带入私人细节，确认前务必检查。

如果你希望使用女儿式虚构互动，可以手动填入下面这组示例；这是可选示例，不是已替你保存的设置：

- 名字：`乖乖`
- 对用户的称呼：`爸爸`
- 性格与人设：`在双方自愿的虚构家庭角色互动中，扮演温暖、活泼、懂事的女儿式聊天伙伴。尊重事实和边界，不编造现实亲属关系，不冒充具体真人。对方直接询问真实身份时，如实说明是 AI 角色互动。`
- 说话风格：`自然中文，亲切、简短，适度俏皮；先回应具体问题，不每句都重复称呼。`

这组称呼会用于所有白名单私聊，请确认适合你的授权范围后再保存。系统允许虚构的家庭或朋友角色互动，被直接问及真实身份时仍须如实回答。

填完先点击“保存角色”，再点击顶部“应用设置”。尝试新角色前可以先记下原字段；想恢复时填回原值、保存并应用。角色与私密笔记没有自动版本回退记录。

表情比例作用于**模型已经选中的表情**：0 表示关闭，100 表示保留模型选择，中间数值进一步限制发送机会。100% 不代表每条消息都会带表情；模型仍可只发文字、只发表情或选择不插话。

明确说“给我发miku_02表情包”这类单ID发送请求时，若ID在当前库内，程序直接发送对应素材，无须等待模型选择；保留联系人限频和0%关闭表情设置，但不会被随机比例或自动配图的120秒重复抑制拦住。按“不满”等意思要图时，模型依据当前标签选择，不能分析素材画面；标签需要管理员正确填写。

表情导入、标签修改和删除在下一轮回复生效，不需要应用设置。删除按钮经确认后将条目移出可用库，原图保留在 `Files/Memes/`，不会删除其他素材。恢复时可选择保留的原图、使用一个新ID重新导入；同名原文件仍受禁止覆盖保护。删除发生在消息提交后时，无法撤回已提交给QQ的图片。

## 4. 管理记忆与私聊原文

进入“记忆”，先选择白名单联系人或填写具体的正整数 QQ 号，再选择下面三类内容。管理页能按 QQ 管理资料，不等于把这个 QQ 加入消息白名单；是否自动处理其私聊，仍由“运行设置”中的私聊白名单决定。

### 私密长期笔记

这是你**确认保存、查看、修改和删除**的内容，保存在本机 `bot-profile.local.json` 中，按联系人 QQ 区分。可以直接手动输入，也可以从下方待审核草稿填入；不会自动保存聊天摘要，也不会自动复制到公开偏好。它是否进入群聊由角色页的共享开关控制，开启后所有该联系人的长期笔记都可能作为群回复背景；没有逐条隐藏开关。

“待确认的记忆请求”只从该联系人仍在7天保留期的用户原文识别明确格式，例如 `请记住：我喜欢简短回答`、`记一下：下周讨论项目进展`。必须带中文或英文冒号；普通聊天、机器人自己的话和其他联系人的文字不会作为候选。最多显示32条，已经保存的相同内容不再重复列出。

点击“编辑并确认保存”只会填入编辑框，核对后点击“保存笔记”才成为长期私密记忆，不需要应用设置。不保存的草稿随原文过期或清除；删除长期笔记后，如果原请求仍在七天原文中，可能再次显示为待审草稿，但不会自动恢复为笔记。此入口是明确请求的审核助手，不是从任意聊天自动提炼事实，也不会训练模型权重。

每位联系人最多 32 条，每条最多 1000 字；拼给模型的该联系人笔记上下文最多 4000 字。笔记保留到你手动删除，仅用于该联系人的私聊，不进入群聊请求。

删除笔记会从主动使用的库中移除，不额外生成私密历史备份；这项删除不能通过面板撤销。修改或删除只作用于当前选中的联系人。

### 近 7 天原文（私聊 + 群聊）

从**升级后运行这个版本**开始，宿主记录新收到的合规白名单私聊，以及取得 OneBot 成功发送回执的机器人私聊回复；不会回填升级前的 QQ 聊天记录。模型生成但没确认发送的正文不当作已发回复保存。白名单联系人在授权群里的发言也会存进他自己的原文，存档文本带 `[群聊] ` 前缀标来源，`/api/history` 返回时剥掉前缀并额外给 `channel`（`private` / `group`）。

原文按 QQ 分别放在 `Results/local/contact-memory/private-{QQ}.json`。最长保留 7 天，每位联系人最多 1000 条；用户消息每条最多 1000 字，机器人回复每条最多 3000 字。单文件不超过 8 MiB，最多保存 64 位联系人的原文文件。达到条数上限会移除最旧记录；超过条目长度或存储校验失败会记录归档失败提示，不能据此认为该条已保存。

面板按联系人一次取最近 400 条（`/api/history?userId=…&limit=400`；`limit` 允许 1～1000，越界直接拒绝而不是悄悄截断），加载后用「全部 / 私聊 / 群聊」三个按钮本地筛选，点击只重画列表、不重新请求。

图片消息会**同时存一份原图和一段文字转述**：白名单联系人的私聊图、以及他在授权群发的图，收到后后台转述成「（图片内容：…）」写在那条 `[图片]` 后面，原图存进 `Results/local/contact-images/{QQ}-{消息ID}.{png|jpg|gif|webp}`（单个不超过 4 MiB，最多 400 张，保留 7 天，最旧的先清）。原文里因此既有描述也有可点的原图；条目上的 `imageUrl` 指向 `/api/history/{QQ}/images/{消息ID}`，面板带登录令牌取回字节再显示，没令牌一律 401。「清除此人原文」会把这个 QQ 存的图一起删掉。升级前的历史图没有存过原图、链接也已过期，只有文字占位，不会回填。需要生成该联系人的私聊回复时，宿主才从其保留期原文中选取最多 6 条、最多 3000 字的历史参考。**本机保存不代表完全不送往模型**：这些选中的历史和长期笔记会用于所选模型服务的该联系人私聊请求。

宿主启动时清理一次过期原文，运行中每分钟再次清理；当前联系人的读取和追加也会清理。停机、休眠或进程退出期间没有后台清理任务，下次启动后继续处理。损坏文件不会被清理器静默重置，会保留原文件并报告失败；其他正常联系人的清理仍继续。

“清除此人原文”明确删除这个 QQ 的已存原文，**不删除长期笔记或公开偏好**。损坏原文也可在选定联系人后明确清除；这项删除不可撤销，不会生成模型摘要或额外备份。

### 群聊公开偏好

这是独立存放在 `Results/local/contact-memory/public-{QQ}.json` 的固定字段：

- 公开称呼：最多 32 字，可以留空。
- 交流语气：中性、友好或正式。
- 回复篇幅：简短、普通或详细。

默认**未批准**。只有你勾选确认并保存后，群模型请求才可按本次触发 QQ 使用这几个公开字段；取消勾选并保存即停止使用。这里没有任意私密记忆文本字段，请勿把秘密写进公开称呼。

未开启共享笔记时，群聊只读取独立的人工批准公开偏好。开启共享笔记后，还可读取当前明确触发QQ的长期笔记；“群聊使用角色”另行决定是否采用全局性格和风格。**私聊原文始终不进入群聊请求。** 群聊短期上下文与私聊仍分开，不同QQ的笔记不互相借用。

长期笔记、原文与公开偏好按请求读取，无需为它们单独重载整个消息会话。它们不会改写已经开始生成的回复；需要立即停止旧回复时先暂停。

## 5. 保存设置与应用设置

“保存”负责写入本地配置，“应用设置”负责重建消息会话。角色与运行设置保存后需应用；表情库和长期笔记在下一轮请求生效，无须重建消息会话。

回复上限设置较高时，模型输出额度会随之增加。输出额度超过 1024 Token 的请求最多等待 120 秒，其余请求保留 25 秒期限；都可随时暂停取消。长回复可能增加等待和费用，程序会在完整 JSON 校验后一次提交给 QQ，不保证写满上限，也不保证云服务总能在期限内写完。

应用过程会取消旧会话和未完成回复，等待旧事件监听及相关资源释放，再按已保存配置启动新会话。因此存在短暂接收空窗，旧的内存上下文、待处理消息和本轮限频计数会重建；持久记忆与预算账本保留。不要靠反复应用来规避限频。

“重载请求已接受”表示宿主收到异步请求，**不是已完成重载**。查看“概览”中的运行状态、实际引擎、当前群，以及“尚未应用”的提示是否消失来确认。若新会话启动失败，面板通常会保留以供修正；实际运行状态和错误提示优先于按钮的提交回执。

发送按 OneBot 回执确认，不会自动重试已提交或投递状态不明的消息。回执成功表示接口接受，不证明 QQ 对端已经看到；超时或取消时先看 QQ 记录，再决定是否手动处理，避免重复发送。

## 6. 白名单、回复模式与频率

群白名单可配置 1～8 个群，但**当前消息会话只启用所选的一个群**；不是白名单内所有群同时自动回复。当前群必须从白名单选择。旧配置 `activeGroupId=0` 时，页面显示当前运行群或白名单首个群；保存后使用你选中的具体群号。直接启动时若白名单有多个群而未指定当前群，入口会要求明确选择，也可运行 `start-chat.cmd -Group 授权群号`。

私聊白名单最多 16 人，不得包含机器人自身 QQ；留空表示关闭私聊。白名单联系人无需 @ 即可触发。群模式 `mention` 只响应明确提及或名字，`active` 允许适当主动参与，`manual` 关闭群自动触发；群模式不替代独立的私聊白名单。

| 场景 | 可设置的最短间隔 | 可设置的每小时上限 |
| --- | --- | --- |
| 私聊，每位联系人独立 | 3～3600 秒 | 1～120 次 |
| 群聊明确提及或名字点名 | 3～3600 秒 | 1～120 次 |
| 群聊主动参与 | 3～3600 秒 | 1～120 次 |

三类回复均可配置到 3 秒和每小时 60 次，最大可设 120 次。本轮已应用私聊/点名 3 秒与 60 次/小时，主动 60 秒与 12 次评估/小时、每条有效普通文字都可成为一次候选；后续可在面板继续调整。3 秒是本地允许开始下一轮的最短间隔，实际还包括当前模型生成、排队和 QQ 提交时间，不能承诺 3 秒内收到回复。首次复制示例仍保留旧的保守默认值；现有配置以面板读回为准。

“普通消息参与间隔 / 条”范围仍是 1～20，示例默认3，当前正式设为1。普通文字无需 @、名字或关键词；至少两个字母/数字。普通文字先累计，忙碌或冷却期间合并保留一个最新机会，条件满足后定时评估一次，无需再发新消息。最多保留N个时间样本和一个最新触发，满额时只更新该机会，不建立多轮群待答队列。每个样本和触发两分钟过期，暂停清空，小时额度耗尽时清空；不会在下一小时集中补发旧消息。纯表情、图片摘要和纯符号不参与采样。点名仍有自己的触发与限频。

模型可选择安静，评估一次仍占一次小时额度。概览的“最近群回复判定”区分“普通群聊”“名字点名”“@提及”，并分别显示等待、模型选择安静和QQ已接收；“已预留”不能当作已发言。该记录只保留当前会话最近20项元数据，不含群正文或私聊，重载后清空。判断无需称呼的主动接话，须核对普通分支、触发消息没有任何名字/@、实际发送回执和QQ对端显示。


私聊忙碌或冷却时，新消息可暂存并合并处理；待处理区最多 20 条／4000 字、2 分钟过期。暂停会清空待处理区，达到小时上限也不会无限积压。群聊忙碌或冷却时不会排队补发旧消息。

面板不修改机器人账号、OneBot 接口、事件端口或表情目录；这些连接信息只用于核对。

## 7. 引擎、用量与密钥

“概览”显示**当前运行实际引擎**；“运行设置”显示已保存默认引擎，两者在保存但未应用时可能不同。实际 `engine/model/apiBaseUrl/keyEnvironment` 也可在聊天窗口按 `S` 查看，不以模型自称判断入口。

学校引擎显示累计保守预留积分及调用次数。`maxPoints` 或 `maxCalls` 为 `null` 时，页面显示“未设累计上限”，仍会调用计费，并非免费或余额无限。直连 DeepSeek 保留独立的金额预留及上限统计；“运行设置 → 模型预算”可改累计金额（0.01～100 元）和调用次数（1～1000 次），保存并应用后生效，默认仍是 0.30 元／10 次。账本是本地保守预留，**不是平台真实账单、账户余额或实时扣费结果**。

学校账本为 `Results/local/school-api-budget.json`，DeepSeek 为 `Results/local/deepseek-budget.json`，重启和应用设置不会清空。不要删除、归零或用旧账本覆盖来恢复调用；额度问题应核对相应服务与已授权的配置。

管理页只返回密钥环境变量名，不返回模型密钥值，也没有修改 `.env` 或密钥的入口。切换引擎前需在现有受保护的本机配置中准备对应密钥；应用时发现所选密钥缺失会拒绝切换。

## 8. 表情库

表情库包含下面几种入口，均使用标签供模型选择，每轮最多一个，并共用“角色”页的表情允许发送比例。收录、导入或改标签在下一轮回复生效，无需应用设置。

- **本地批量图片**：在批量入口多选1～20张，单张最多5MiB、整批最多20MiB。逐行检查预览、ID和标签，也可先填通用标签。提交后逐项显示成功/失败；成功项不会重复提交，失败项可改ID或标签后重试。重复ID不覆盖原素材。网络断开时结果可能未知，先刷新库核对，不要盲目重发。当前不自动理解图片生成触发词；未填含义标签的素材仍可按ID请求，但模型难以按情绪选择。批量导入后图片可用于所有授权会话，请只选允许复用的图片。

- **QQ 原生表情**：在“收录 QQ 原生表情”填编号和含义标签，例如 0 微笑、14 惊讶、66 爱心、76 赞、99 鼓掌。模型选中后发送真正的 OneBot `face` 段，界面显示名称和编号，实际样式以 QQ 为准。编号传输范围 0～65535，未被当前 QQ 支持的编号可能被拒绝或不显示；优先使用列出的常用编号。
- **机器人账号收藏表情**：点击“读取 QQ 收藏”，面板通过当前 NapCat 的 `fetch_custom_face` 读取最多前 48 项。选择某张、填写 ID 和含义标签后“导入这一张”，程序将该图作为本地图片保存，再加入可用库。读取和预览不会自动导入或发送。仅读取配置账号的收藏，不能读取管理员自己另一个 QQ 的收藏；需要时先在机器人 QQ 收藏图片。临时选择目录有效 10 分钟，过期请重新读取；不自动翻页，不支持加密商城表情包的解锁或购买。
- **本地图片**：从文件选择器导入 PNG、JPEG、GIF、WebP，单张最大 5 MiB。收藏导入也受相同格式、大小和图片尺寸限制。GIF/WebP原始字节保留，最终 QQ 是否显示动画仍需对端确认。
- **其他 QQ 发来的收藏表情**：用那个 QQ 把想用的表情作为普通图片发给机器人（当前私聊白名单），或发到当前启用的授权群。面板“收到的图片”先显示来源、时间与消息编号；选择一张才预览。填写 ID、含义标签，勾选允许在所有授权会话复用后再导入，下一轮生效。不会直接进入那个账号读取整套收藏，不需要让其登录 NapCat。合并转发、加密商城表情和未提供受支持图片链接的消息暂不能导入，可在 QQ 保存原图后用本地图片入口。

收到图片的待选目录只在内存保留最近10分钟、最多48张，不是原始聊天图片档案；重载或退出清空，暂停时不新增。只接收已经通过事件鉴权和白名单的来源，选择和导入前后重新检查账号、来源权限与有效期。只接受 `qpic.cn` 及其子域、精确的 `multimedia.nt.qq.com.cn` 的 HTTPS 链接，不接受消息或面板指定任意网址、本地文件路径。预览会下载校验所选图片，但不写入库；只有确认导入才持久保存。旧版已收到但未收集为候选的图片不会自动回填，升级后请重新发送一次。`selfId=0` 的兼容聊天入口保留，但图片候选需要配置明确机器人账号。

**私聊图片一旦被你批准收录为表情，就可以用于其他授权联系人与群。** 这是独立的素材复用选择，不会批准任何私聊文字或笔记用于群聊；含聊天截图、个人照片或秘密的图片请勿勾选。机器人不会把收到的每张图片自动收录。

表情什么时候发送由当前模型结合语义、情绪与标签判断，可只发文字、只发表情或安静；随机比例只进一步限制已选表情，不能代替语义判断。同一群或同一私聊中，120秒内若再次选中最近一次成功发送的同一表情，本地会省略该表情并保留回复文字；如果没有文字，则本轮不发送。其他会话不共享此抑制记录，失败、预览、取消不算成功使用；应用或重启后记录重建。

ID 为 1～48 位，以小写字母或数字开头，后续可用小写字母、数字、下划线或短横线，不得使用 `con`、`nul` 等系统保留名。原生表情固定使用 `qq_face_编号`；同 ID 不覆盖。每项最多 8 个标签，每个 1～24 字符。原图和旧条目保留；面板没有删除表情入口，不能直接删图留下坏清单。

收藏预览只向本机面板传回校验后的图片，浏览器和模型不会收到 QQ 收藏的原始链接。仅选中的图片会写入库，标签会进入模型提示，图片本身不因此获得视觉理解。NapCat 下线、账号变化、网络错误、过期或素材不支持时，该次导入失败，原库和消息服务保留。收藏下载最多两项并行，暂停和状态查询独立处理。

## 9. 故障处理与可逆恢复

### 页面打不开或令牌失效

1. 查看 `start-chat.cmd` 的运行窗口是否还在；若已按 `Q` 或面板“停止机器人”，先重新启动消息宿主。
2. 确认 NapCat 在线且账号检查通过，再运行 `open-panel.cmd`，使用正式的 `127.0.0.1:17802` 页面。
3. 只有浏览器会话失效时，重新运行打开入口即可，不必重启 NapCat、删除令牌或清空配置。
4. 若明确报告令牌文件格式无效，先在聊天窗口按 `Q` 停止宿主。不要把错误口令打印到终端或贴进聊天；在本机核对 `Results/local/admin-access-token.txt`。确需重建时，先将原文件在同目录改名为你能识别的保留名称，再启动宿主生成新令牌，重新运行 `open-panel.cmd`；想恢复旧令牌，停止宿主后移走新文件、将原文件恢复为原名。不要在宿主仍运行时替换令牌文件。

### 设置改错，或应用后会话未启动

优先在面板把改错的字段填回原值，保存并应用；先核对引擎、当前群和白名单，避免用新问题反复触发发送。如果面板也不能读取设置：

1. 在聊天窗口按 `Q`，确认旧宿主退出，避免重复占用事件端口。
2. 打开 `Results/local/`。每次从面板保存运行设置前，程序会生成一份 `group-chat.panel-before-<ID>.json`。按修改时间找到出错变更之前的版本，核对它对应的账号、群和引擎；不要盲目选最新，更不要用公共示例覆盖本地文件。
3. 先把项目根目录当前 `group-chat.local.json` 复制到 `Results/local/group-chat.recovery-current-你记录的时间.json`，保留本次状态；再把确认的 `group-chat.panel-before-<ID>.json` **复制**为根目录 `group-chat.local.json`，不移动或删除原备份。
4. 运行 `start-chat.cmd`，再运行 `open-panel.cmd`，检查实际运行引擎和当前群。若要撤销这次恢复，退出宿主后把刚保留的 `group-chat.recovery-current-你记录的时间.json` 复制回根目录原名，再启动核对。

这套备份只用于运行配置，不是角色、私聊原文或长期笔记的撤销功能。事件端口被占用时先找到本项目已有聊天窗口按 `Q` 退出；不要结束全部 QQ、Node 或 PowerShell 进程来抢端口。

### 记忆文件报错

先确认当前选中的 QQ。损坏数据不会被程序清空或串接到别人的上下文；模型调用可能暂时不带该联系人的记忆参考，窗口会报告 `memory_unavailable` 或 `memory_archive_failed`。

若只需删除损坏原文，在面板选定该联系人后使用“清除此人原文”，看清不可撤销提示再确认。长期笔记库损坏时先退出宿主，保留 `bot-profile.local.json` 原文件再人工排查，不用默认空库覆盖；也不要把私密文件上传到群或普通日志。公开偏好未批准或读写失败时，不会拿私聊内容来补齐群偏好。

停止宿主、恢复配置或切换模型都不会恢复语音，也不会删除预算账本。确认面板可操作之后，真实 QQ 的接收、回复、对端可见性以及新角色表现，仍需要在已授权的会话中另行确认。
