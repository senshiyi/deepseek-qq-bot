## 2. QQ 与 Windows 应用输入路由

先记下 QQ 当前麦克风、扬声器名称或自行截图，便于恢复。设置：

| 环节 | 应选设备 |
| --- | --- |
| QQ 扬声器 | 用户耳机，例如 XIBERIA K9U PRO |
| QQ 麦克风 | CABLE Output (VB-Audio Virtual Cable) |
| 本工具输出 | CABLE Input (VB-Audio Virtual Cable)，方向 render |
| 本工具输入 | 指定 QQ 根进程及其子进程的播放流 |

名称中 Input/Output 是从虚拟线缆自身看，容易选反。群友声音不经过本工具的输出队列；机器人的测试音也不应播放到 QQ 正在输出的同一条采集通道。

关闭 Windows“侦听此设备”，不另开软件把 CABLE Output 监听到 QQ 播放通道。首轮所有人佩戴耳机，排除远端外放回音。

当前 QQ 若没有内置麦克风选择入口，可在 Windows“设置 → 系统 → 声音”的音量合成器/应用设备首选项中，把 QQ 的输入设备设为 **CABLE Output**。先记录 QQ 应用输入偏好的原值，系统默认麦克风、默认播放及其他应用的设备保持原样。应用偏好值只是选择意向，还须查看 QQ 实际活动采集会话使用的端点。

同一可执行路径启动的两个 QQ 实例可能共享应用偏好。历史上对一个 QQ 音频进程选择 CABLE Output 后，两个实例的采集会话都转到该端点，因此不能把同机另一 QQ 当作路由独立的远端。首轮使用手机或另一台电脑作对端，并分别记录本地与对端设备。

历史回退也有区别：11:32 已把 QQ 应用输入偏好恢复为“默认”，但 11:33 读回时仍有 QQ 活动流使用 CABLE Output。恢复时先退出工具，把 QQ 内设备和 Windows 应用偏好恢复为记录的原值，再结束并重新建立通话音频流；必要时重启目标 QQ，重新枚举 PID，并检查实际活动输入端点。不能仅凭偏好下拉框已恢复就认定活动流已恢复。相应历史见本地 `qq-app-input-preference-*.json`、`qq-app-input-route-readback.json` 和 `after-app-preference-revert.json`。

## 3. 用户确认后进行真实群测试

用户先确认机器人 QQ 窗口/账号、测试群、测试时段和参与者知情。人工加入群通话。工具的群名参数只是标记，不会替用户加入或校验当前群。

1. 执行 `devices`、`qq`，核对当前 QQ 可执行路径/版本，用 `configure` 保存设备与根 PID，再 `check`；QQ 重启或更新后不得沿用旧进程快照。记录 QQ 实际活动输入为 CABLE Output、播放为耳机，并确认独立对端就绪。
2. 启动 `run --test-group "已同意的测试群" --minutes 10`，先按 L，只让一位远端成员讲话。确认电平随其声音变化；让其停顿，确认信号回落。当前电平统计累计，需重新 L 停止/开始清零后比较。
3. 对方静音，重新开始收听，再按 P。请对端明确反馈是否听到固定音，未听见则记录发送失败并分段定位；本机 completed 只表示本地播放流程结束。本机采集应保持静音或底噪，且须在最终工作的 QQ 输入路由下复核。若电平出现测试音，先查软件监听路径，不认定已隔离。
4. 启动测试前可用 `configure --tone-ms 5000` 将固定音设为 5 秒；在通话中按 P 再按 X，便于观察停止。也可播放较长的本地 PCM WAV（`--wav`、W）。远端说明是否停声；本地显示只代表应用取消/释放耗时。M 之后按 P 不应发声，解除 M 后也不应恢复旧声音。
5. 远端取消静音，重复固定音测试。只有此时出现回传，优先检查远端扬声器和监听，不把它当作按进程采集隔离失败的直接证据。
6. 经参与者同意，拔掉/恢复输出设备、结束并重新打开 QQ，确认错误可见、不会换默认设备、重新选择后能恢复；此操作会影响当前测试通话，应在该测试时段内做。
7. 按 Q 退出，按第二节恢复 QQ 内设备及 Windows 应用偏好，重新建立音频流后核对实际端点。若本轮决定保留联调路由，也须明确记录保留项与恢复方法。

第一里程碑验收须同时有：真实远端讲话进入程序、真实远端听见程序测试音、本机输出不直接进入采集。任一项未证实则保持“待验证”。当前版本没有自动语音活动检测或 ASR，所以“没有自我唤醒循环”还需后续语音链路再次验证。

本轮已取得这三项的单次受控证据：独立对端确认 23:15:48 的固定音可听，同次 8 秒采集 peak/rms 为零；23:16:19～31 对端持续讲话时，程序收到非零音频。23:16 路由快照显示当前 QQ 活动采集端点为 CABLE Output，六种系统默认设备角色仍为原 XIBERIA 耳机/耳麦。重复运行、外放/多人回音与故障恢复不在这次通过结论内。

## 4. 延迟记录口径

- 当前目标：先保证路由正确，再实测固定声音启停；不承诺 QQ 内部缓冲上限。
- 后续短问答开发目标：用户说完至远端首次听见回复尽量 ≤ 2 秒，P95 另记；有效插话至远端停止尽量 ≤ 300 ms。此为目标，不是当前已实现或实测结果。
- 当前实际值：本轮独立对端已确认听见固定音，但未用共同计时来源测量远端首音或停止延迟。早期约 0.831 秒、本轮约 0.830 秒均为 800ms 固定音的本地播放及清理耗时，不能当作远端延迟。
- 真实测试可在参与者同意后从远端录下测试音和按键提示，或用同一计时来源标记事件。至少记录样本数、中位数、P95、网络环境；不可用本机 X 的耗时替代远端停止时间。
