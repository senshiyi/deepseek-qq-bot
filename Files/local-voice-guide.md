# 本地语音运行说明

本阶段使用 sherpa-onnx CPU 中文流式识别、Windows Huihui 中文音色和既有 QQ 音频桥。模型和语音合成都在本机运行。只有选择 `deepseek` 模式才发送识别后的问题及有界文字上下文给 DeepSeek；不上传原始群音频。

## 准备与启动

在项目根目录打开 PowerShell 7。首次准备或重新安装依赖后：

```powershell
pwsh -NoProfile -File .\Files\Install-LocalAsr.ps1
pwsh -NoProfile -File .\Files\Install-LocalAsr.ps1 -VerifyOnly
Copy-Item .\Files\bot-config.example.json .\bot.local.json
.\start.cmd devices
.\start.cmd qq
```

已有 `bot.local.json` 时跳过复制，保留手动配置。下载脚本只从固定模型修订取得四个文件并校验哈希；模型约29.54 MiB，安装到 `Models/`，原下载缓存放 `Cache/`。删除缓存不删除正式模型。下载地址、哈希与 Apache-2.0 来源写入模型清单。没有 CUDA 依赖。

按 [audio-routing.md](audio-routing.md)让机器人 QQ 通过 CABLE Output 录音、向耳机播放。更新 `config.local.json` 中的 QQ 根进程 PID，程序输出必须为 CABLE Input。不要用 CABLE In 16ch，不修改系统默认设备。QQ 重启后重新枚举 PID。

用户人工登录、进入已授权测试群通话；参与者首轮戴耳机。按顺序运行有限会话：

```powershell
# 只收听和断句，不回复；默认不在日志输出识别正文
.\start.cmd bot --test-group "已同意的测试群" --mode listen --seconds 30

# 名字/明确触发后用本地语音说固定句子，不调用DeepSeek
.\start.cmd bot --test-group "已同意的测试群" --mode fixed --seconds 60

# 配好正式API密钥和预算后才选此模式
.\start.cmd bot --test-group "已同意的测试群" --mode deepseek --seconds 60
```

`bot`立即开始收听，默认60秒，允许5～300秒；到期停止。M静音/解除、X停止当前回复、S状态、Q或Ctrl+C退出。解除静音不恢复旧回复。程序使用本地独占会话锁，不允许同一项目同时启动两套机器人；不要在机器人发声时另开测试音命令。

## 唤醒、断句和多人

首轮请说“**机器人，你好**”或“机器人，今天怎么样”。每次提问明确唤醒，保持有界多轮上下文。配置中的名字默认为“小深”，也接受“机器人”；离线测试中“小深”被识别成“小身”，所以不把小深唤醒计为已通过，推荐先用“机器人”。不自动把所有同音字都当唤醒词。

机器人说话期间继续收听。“停一下”“停止”“别说了”，或先喊名字再问新问题，会尝试取消旧回复；能量门限用于排除瞬时小噪声，流式识别识别到有效词后才触发，不能保证任何口音都立即识别。当前小模型采用约0.8秒尾部静音断句；自然度和抢话延迟须真实测量。

这是多人混合音轨，没有可靠成员身份。请轮流讲话；同时说话可能识别错误，重新唤醒并重述。程序不根据群语音或文字执行电脑命令或任意文件操作。

## 密钥与0.30元预算

把根目录 `.env.example` 复制为 `.env`，仅在本机编辑：

```text
DEEPSEEK_API_KEY=你的正式API密钥
```

也可由启动终端提供同名环境变量。不要把密钥发到聊天或QQ群，不写入命令历史、截图、普通日志或提交。`.env`与本地配置已被忽略。未配置密钥时 `deepseek` 模式在收音前失败，`listen`和`fixed`仍可运行。

本轮用户授权的累计上限是 **0.30元**。程序使用 `deepseek-flash`、关闭思考、流式读取正文，输出最多256 tokens；只支持本阶段的文字传输。按当前高峰单价和输入UTF-8字节数加保守余量，**先预留本次最坏费用，再发送请求**。累计预留和最多10次调用计数持久保存为 `Results/local/deepseek-budget.json`，重启不会自动归零；请求取消或失败不退款式扣回，避免未知用量造成超支。达到上限拒绝新调用。

预算记录是本程序的保守预留，不是账户余额查询或官方账单，也不约束其他软件使用同一个密钥。不要删除预算文件来绕过本轮限额；提高限额需用户重新授权。模型/价格改变时先重新核对，不能沿用旧定价直接切换。

## 诊断和恢复

```powershell
# 明确选定的本地测试WAV；最多30秒，不收音、不播音、不上传
.\start.cmd asr-file --wav "测试句.wav"

# 正式只读快照，不收音或更改设备
pwsh -NoProfile -File .\Files\Get-AudioRouteSnapshot.ps1 -Label before-bot
```

默认不记录识别正文。需要诊断真人识别准确率时，可在 `bot.local.json` 将 `logTranscripts`临时设为true，测试结束恢复false；这会把识别文字输出到终端/调用方日志，应只用于已同意范围。原始群音频始终不保存。

缓冲超过上限、缺帧或输入格式改变时，程序丢弃旧语句并重置识别，要求重问；不继续回答几秒前的积压语音。网络失败停止本轮，后续明确唤醒可重试；音频设备失败不自动切到默认扬声器。若报告“资源尚未确认释放”，该语音实例锁定，退出程序后检查设备，不把这类超时当成功。

退出机器人后如需恢复普通聊天，把Windows音量合成器的QQ**应用输入设备**切回“默认”，并重新核对QQ实际录音流。保留系统默认耳麦不变。复核方法见路由文档。

## 当前图片边界

用户选择普通账号收图路线。OneBot图片入口与语音分开部署，必须验证NapCat和当前QQ群通话稳定共存后才计自动群收图。没有真实消息事件时，手动导图或模拟事件只能作为开发测试，不能写成自动收图完成。

## 计时的含义

`local_first_pcm`记录输入最后一个有效能量包到本地播放器首次读取非零PCM的耗时；`interrupt`记录输入能量起点/识别到触发词至本地Speak清理的耗时。两者都不包含QQ与远端缓存，不等于群友实际听到的首音/停止延迟。真实端到端指标需独立设备计时并单列记录。
