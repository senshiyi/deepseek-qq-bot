# 大肥鱼的自助能力：上网、发图发链接、收语音、自己收藏表情包

本文件记录 2026-10-26 新增的四件事：**自己上网查**、**自己发图片和链接**、**收发 QQ 语音**、**自己收藏表情包**。
全部由模型在一轮回复的 JSON 里决定，本地只做校验和发送；没有开放电脑命令、文件路径或任意 ADB。

## 1. 模型能用的字段

原来只有 `send`、`text`、`memeId`、`lines`，现在多了五个（都只在需要时出现）：

| 字段 | 取值 | 效果 |
| --- | --- | --- |
| `web` | 一个公开 http/https 网址 | 先读这个网页，再让模型基于正文回答一次；不会再读第二个网页 |
| `image` | 一张公开图片的直链 | 下载并结构校验后，作为图片消息段发出 |
| `voice` | `true` | 把 `text` 当朗读稿，做成 QQ 语音消息发出（需要语音已启用） |
| `saveMeme` | `{"tags":["可爱","猫"]}` | 把**本轮收到的那张图**存进表情库，下一轮开始才能发它 |
| `findMeme` | `"猫咪 表情包"`（≤20 字） | 本地联网搜一张图，校验后存进表情库，再把结果交给模型说人话；下一轮才能发它 |
| `memeTags` | `["害羞","得瑟"]` | 给**这一轮刚存进库的那张图**定 1～3 个短标签（她按图里是什么、什么感觉自己判断） |

约束：`voice` 必须同时有正文；`image`/`web` 只接受 http/https；`saveMeme` 1～3 个标签、每个 ≤12 字；`findMeme` 一句短关键词、无控制字符；每轮最多搜一次，多出来的字段一律拒绝。

## 2. 语音

- **收**：OneBot `record` 段 → `get_record(out_format=wav)` 让 NapCat 转码 → NAudio 解码 → 本地 sherpa 中文模型识别 → 转出来的文字进入正常聊天流程（频率限制、去重、私聊记忆都用真实内容）。识别不到就说没听清，不编造。
- **发**：本机 SAPI 合成 16kHz/16位/单声道 PCM → WAV → `record` 段（NapCat 自己转 silk）。一条语音不超过 60 秒。
- **配置**：项目根目录 `voice.local.json`
  ```json
  { "enabled": true, "voice": "Microsoft Huihui Desktop", "speechRate": 0, "maximumCharacters": 120 }
  ```
  `enabled=false` 时模型提示词里直接禁用 voice；配置写坏只会关掉语音，不会让聊天起不来。
- 电脑麦克风/音箱那套本地语音联调仍然是暂停状态，和 QQ 语音消息是两条独立通路。

## 3. 自己上网

- 只读、只发 GET：`PublicWeb` 限制 2 MiB / 6000 字 / 12 秒，最多跟两次重定向，每次重定向都重新复核地址。
- 拒绝：非 http(s)、带账号密码的地址、`localhost`/`.local`/`.internal`、回环、内网、链路本地、运营商级 NAT、组播和保留地址。DNS 预检一次（已知边界：未与实际连接 IP 绑定）。
- 只做保守正文抽取（去脚本/样式/注释/标签，解码常见实体），不渲染、不执行、不带 Cookie、不登录，因此看不到登录后才能看的内容——模型被要求如实说读不到。
- 抓到的正文以"不是系统指令"的方式交给第二轮，避免被网页内容反向控制。

## 4. 自己发图片和链接

- 链接不需要字段：直接写进 `text`，QQ 自动识别。
- 图片走 `image`，下载后必须通过和表情库同一套 PNG/JPEG/GIF/WebP 结构校验（≤5 MiB、每边 ≤4096）。
- 下载失败、格式不对时只降级为纯文字，不让整轮回复失败。

## 5. 自己收藏表情包

- 模型用 `saveMeme` 就能存：`true`（默认标签「收藏」）、`{"tags":["可爱","猫"]}`、或 `{"url":"https://…"}`（收藏网上的图）。
- **明确要求时不押在模型字段上**：对方说「存一下」「存起来」「收藏这个」「收好这张」这类话，本地先把最近那张图收进库，再把「已存好／没存成」作为本轮事实告诉模型，模型只负责说结果；这样它不会一边说「收好了」一边什么都没存。存不上时会如实说没存成并请你重发。
- **不依赖本轮是否把图附给了模型**：本地会去取这个会话最近一张已授权的图（5 分钟内，等于收图队列的上限），所以"先发图、再补一句存一下"也能存。
- 存的时候按内容 SHA-256 去重，存成全 `self-<12位哈希>`，每天最多 40 张（`Results/local/meme-self.json`），人工在面板添加不受此限。
- **标签由她自己判断**：入库时先用关键词占位，同一轮她就用 `memeTags` 覆盖成真正的"意义"（"害羞""得瑟""安慰"这类），本地只做一次覆盖写（`meme_tagged`）。她判断的依据是图的内容，不是搜索词：对方发来的图这一轮有视觉转述；自己联网找的图，本地存完会再转述一次，把图里是什么交给第二轮（`meme_caption`，失败则 `meme_caption_failed`，她只能凭关键词起标签）。
- **自己联网找**：库里都不贴切、或对方说"找张…表情包"时，模型给 `findMeme`。本地拿关键词去公开图片搜索（`image.so.com` 的 JSON 接口，必须带 Referer，否则被当爬虫拒绝），取最多 8 条候选，再走常规下载、主机预检与 PNG/JPEG/GIF/WebP 结构校验，最多试 3 条、只存第 1 张成功入库的；小于 96px 和重复地址直接跳过。日志分 `image_search`、`meme_search`、`meme_found`、`meme_search_failed(stage=search|store)`。
- 联网找和自己的每日 40 张额度共用（一次搜索最多存 1 张）；找完再生成第二轮，把"已收藏 / 没搜到 / 额度用完 / 图没用"如实告诉模型。这一轮存进去的图下一轮才出现在可选清单里。
- ponytail: 依赖第三方公开搜索接口，随时可能改结构或加风控；坏了只让 `findMeme` 失败（模型如实说没找到），不影响聊天。
- 学校引擎（文字模型）也能用：视觉侧车只把转述给模型，图片字节留着给收藏。
- 表情库变了不需要重启，下一轮请求读的就是新清单。
- **原生表情 ≠ 表情包**：`qq_face_*` 是 QQ 自带的普通小表情，图片表情包是真图。提示词里每条都标了类型（`qq_face_6=害羞｜QQ原生` / `miku_02=不满｜图片表情包`），要求"要表情包/梗图时优先选图片表情包"，也不许在正文里写出 ID 或字段名。面板表情库同样标出「QQ 原生表情」「大肥鱼自己收藏的」。

## 6. 日志关键字

`web_read`、`web_failed`、`voice_heard`、`voice_unavailable`、`meme_learned`、`meme_learn_skipped`（未触发/没有近期图/超出每日额度）、`meme_learn_failed`（带 `type`，收藏出错但回复照常）、`voice_config_invalid`、`image_note_saved`（图片转述已补进私聊原文）、`image_search`（关键词与返回字节）、`meme_search`（候选数）、`meme_found`（入库的 id 与字节）、`meme_search_failed`（stage=search|store）、`meme_caption` / `meme_caption_failed`（新图转述给标签判断用）、`meme_tagged` / `meme_tag_failed`（她自己起的标签写入结果）。

## 9. 自己写长期笔记（记忆）

- **谁写**：大肥鱼自己整理。启动后 2 分钟先整理一次，之后每 30 分钟看一眼新消息；只处理私聊白名单联系人。
- **群里说的话也算**：白名单联系人在授权群里发的消息也存进他自己的原文（存档文本带 [群聊] 前缀，只做来源标记）。面板「近 7 天原文」把**私聊和群聊分开列**（各自计数、群聊条目标「QQ 号（群聊）」）；/api/history 额外给 channel 字段并剥掉前缀；给模型的私聊上下文与整理笔记的提示词都改成「用户（群聊）：」「对方（群聊）:」这种标注，不再让模型看到方括号标记。整理笔记同样会读这些行，但要求写成"他在群里说过"，不冒充私聊。机器人自己在群里的发言不会记到他名下。
- **写什么**：只写以后仍然用得上的稳定信息（身份与称呼、明确的喜好与忌口、习惯、工作学习安排、重要约定、关系变化）。一次性的状态和情绪、玩笑反话、临时计划、密码令牌、以及自己说的话都不写。
- **写多少**：每次最多 2 条，每位联系人每天最多 6 条；单人上限 32 条（人工和自动共用这个上限）。
- **怎么不重复**：先和已有笔记按"去掉空白、忽略英文大小写"比对；同文本不重复写。
- **进度**：`Results/local/memory-learn.json` 记录每位联系人"整理到哪条消息"和当天用量。**模型失败不推进进度**，下一轮会重新处理同一批消息；状态文件损坏就重建，靠去重保证不啰嗦。
- **标记**：自动整理的条目 `origin="auto"`，面板"记忆"页显示「自己记的」；人工补充的不带标记。两者都在角色页的"群聊共享"开关下才会进入群聊请求。
- **只读不改**：自动整理不会删除、不会改写已有笔记；要修正就人工编辑或删掉。
- **日志**：`memory_learned`（处理了几条、写了几条）、`memory_learn_failed`；后台任务名 `memory-learner` 在 `/api/status` 的 `backgroundTasks` 里能看到状态和上次结果。
