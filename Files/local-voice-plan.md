# 本地语音与 DeepSeek 对话实施计划

日期：2026-10-19。沿用当前项目，继续实施，无新增审批关卡。

## 已确定的边界

固定音三项核心通路已通过独立设备 QQ 测试，见 [milestone-1-results.md](milestone-1-results.md)。用户选择本地识别与本地合成，语音留在本机；识别后的问题、上下文和所选图片发送至 DeepSeek 正式 API。没有开通腾讯云服务。

资源快照：可用内存约 17.95 GiB，GPU 空闲约 6842 MiB；首版使用 CPU 小型流式识别，避免新增 CUDA 依赖。复用已安装的 Microsoft Huihui Desktop 中文音色，本地按短句合成，不承诺已达到自然人声。

## 结构与实施步骤

保持既有音频诊断命令。新能力继续放入 `Files/AudioBridge`，按职责分文件，不建立无关框架。

1. **本地 ASR**：核对 sherpa-onnx 官方 Windows/.NET 包与 CPU 流式模型；模型放 `Models/`，下载缓存放 `Cache/`，记录来源、许可和哈希。把 QQ 的浮点/PCM 混合音轨转为 16 kHz 单声道；采集回调只写有界队列，识别在独立消费者运行。积压时丢弃整个旧段并重置，禁止越来越晚地回答。
2. **本地 TTS**：Windows 中文音色按短句合成 PCM，在显式 CABLE Input 播放；音量和语速可配。取消时停止合成与播放，关闭文件/内存流，不把声音播到默认扬声器。
3. **对话控制**：识别部分结果与最终结果分开；名字唤醒或明确停止词触发，闲聊不自动抢答。识别保持运行；有效插话取消旧轮次，清空旧音频，代号拒绝迟到结果。回复历史只提交实际完成朗读的短句，未播放内容不入历史；半句取消保守记录为已打断。
4. **DeepSeek**：正式 HTTPS SSE，`deepseek-flash`、关闭思考、只消费正文 delta；短句分段合成，设置超时、输出和历史上限。密钥只用环境或本地忽略配置，不读取其他软件的密钥，不输出密钥。
5. **入口与图片隔离**：提供明确的 bot 启停/静音/状态入口；实时语音与 OneBot 图片消息入口分别失败。先实现带群号/时间/消息ID的有界图片上下文；只有真实 NapCat 群事件联调后才计自动收图完成，不自动修改 QQ 客户端。

## 有意义的验证

- 模型本机加载、固定中文测试句识别与资源占用；不能用模拟结果宣称实际 ASR 质量。
- 固定回复先在授权 QQ 通话中检查断句、音量、可懂度和回采。
- 无硬件测试覆盖取消后的生成结果/合成结果/音频不得进入新轮次，排队片段被清空，静音不续播，以及实际已说历史的边界。
- DeepSeek 密钥和费用范围准备后才做真实 API 短问答，记录“说完→首次出声”。网络失败停止该轮、允许后续重试；音频故障不切回默认设备。
- 真实 QQ 测试分别记录多轮、插话、无自触发、图片及多人混音；无法逐人归属时不声称识别具体成员。
