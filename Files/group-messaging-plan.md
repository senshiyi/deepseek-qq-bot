# 群消息与表情包实施记录

日期：2026-10-20。用户明确要求暂停语音系统，待再次要求继续才恢复。本阶段不采集、不播放、不联调语音，也不修改系统音频设备。

## 交付目标

沿用普通 QQ 账号和 OneBot/NapCat 路线，提供文字、QQ 内置表情及本地表情包发送，群消息触发回复、表情包选择与预览。QQ 登录由用户操作；不假设桌面 QQ 与独立客户端能同时稳定登录同一账号。

## 实施边界

- 发送目标只来自本地群白名单，模型不能指定群号、文件路径或任意 API。
- 手动发送默认预览；实际发送需要明确 `--live true`。自动模式同样明确区分预览和实际发送。
- 先支持手动、@/名字触发、受限主动参与三种方式；用户未决定时采用 @/名字触发，不擅自开启定时刷消息。
- 排除机器人自己的事件、事件去重、过期拒绝、频率限制；忙时只保留有界上下文，不排队补发旧回复。暂停、停止及过期结果在发送前再次检查。
- 本地表情包只从清单选择。明确命令可导入本地图片；不根据群内容读任意文件。GIF/WebP 可以作为图片消息发送，是否显示为客户端原生收藏表情需真实验证。
- 复用 DeepSeek 正式 API 和已有0.30元累计预算，不重置账本。未授权扩充额度时，到上限停止新的AI请求。

## 文件职责与验证

1. `OneBotMessageClient`：受限回环 API、鉴权、发送回执；模拟HTTP验证段格式、白名单、超时及不自动重试。
2. `MemeLibrary`：表情包清单、格式/大小/路径边界、明确导入；提供原创文字反应图和来源说明。
3. `GroupChatPolicy`：消息解析、自己/重复/串群过滤、触发、限流、暂停和有界上下文；用假时间和并发事件验证。
4. `GroupChatRuntime` 与命令：OneBot事件入口、DeepSeek JSON决策、图片上下文、控制台启停和预览。异常不得启动语音或执行电脑命令。
5. 独立代码审查与本地HTTP集成演示。真实群发文字/图片单列验收，模拟结果不写成QQ成功。

NapCat 尚未部署时继续完成代码、资产、配置模板与本地集成；部署准备及用户登录条件单独说明。
