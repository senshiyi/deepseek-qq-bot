## 当前能运行什么

- 只读列出活动输入、输出设备和 QQ 根进程树；明确选择目标实例并保存本地配置。
- 在用户确认的测试群和时段，手动开始采集指定 QQ 进程树，查看音量电平和格式。
- 向指定播放设备发送 440 Hz 固定测试音，或指定的 PCM WAV 文件；手动停止、静音及查看状态。
- 播放替换等待旧播放器退出；有界 PCM 队列及对话代号拒绝过期数据。解除静音不会恢复旧声音。
- `bot` 提供 `listen`、`fixed`、`deepseek` 模式：本地识别、明确唤醒、按短句合成、有效停止词取消，以及只保留完整朗读短句的有界历史。混合群音轨不能对应具体 QQ 成员。
- DeepSeek 使用正式 `deepseek-flash` SSE，仅朗读正文；调用前保守预留费用，本轮累计最多 0.30 元、最多 10 次调用，账本持久保存。
- OneBot 回环图片入口已实现群范围、时间和鉴权校验；本机模拟 HTTP 验证已通过，尚无真实 NapCat 群图片接入证据。
- 手动音频工具默认 10 分钟、最多 30 分钟；`bot` 默认 60 秒、范围 5～300 秒；到期关闭。原始群音频不保存、不上传，不把收到的音频直接回送。

## 环境和启动

Windows 11；最低需支持按进程采集的 Windows build 20348；.NET 10 SDK。当前机器已有 .NET 10.0.300，使用 NAudio.Wasapi 3.2.0，依赖版本和内容哈希见各工程的 `packages.lock.json`。

在本目录打开终端：

```powershell
.\start.cmd help
.\start.cmd devices
.\start.cmd qq
```

双击 `start.cmd` 只显示帮助。首次构建需要访问 NuGet；缓存放 `Cache/`。项目的 `NuGet.Config` 只使用官方源并清除本机失效的旧 fallback，不修改全局 NuGet 设置。

`devices` 的 `render` 是程序可播放到的设备，`capture` 是录音设备；列表中有设备不代表路由已验证。`qq` 只列根进程，包含子进程数量。多组 QQ 不代表已经确认是哪一个账号：必须由用户对照自己的 QQ 窗口选择，不自动猜测。QQ 重启后重新执行 `qq` 并更新 PID。

驱动获授权并安装后，从 `devices` 复制 **CABLE Input** 的 `render` ID；从 `qq` 选择对应机器人桌面 QQ 的根 PID：

```powershell
.\start.cmd configure --pid 12345 --output "从devices复制的完整ID" --volume 0.12
.\start.cmd check
```

配置存本目录忽略的 `config.local.json`。也可用 `--config "完整路径"` 指定。示例见 [Files/config.example.json](Files/config.example.json)。`check` 只确认进程和播放端点存在，不确认 QQ 正在通话或麦克风正确。

真实联调前须由用户指定测试群、同意本次时段、人工登录并加入该群通话。只在这些条件已满足后运行：

```powershell
.\start.cmd run --test-group "已经同意的测试群" --minutes 10
```

程序本身不能验证当前 QQ 窗口是否真的处于写明的群，需人工对照。此命令也不会自动开始收音或发声。

也可在确认已经进入授权群通话后执行有限测试，适合逐段联调：

```powershell
.\start.cmd probe --test-group "已同意的测试群" --seconds 10
.\start.cmd tone --test-group "已同意的测试群"
```

`probe` 会立即收听 1～30 秒，只报告累计电平，不保存音频；`tone` 会立即播放一次并等待本地完成。远端确认听见后，令远端全员静音，再用 `probe --test-group "已同意的测试群" --seconds 8 --tone-at 3` 检查固定音是否进入采集。只有明确提供 `--tone-at` 才会在探测中播放。命令的 completed 表示本地流程结束，远端可听性仍需人工确认；它不等于真实 QQ 验收成功。

| 按键 | 操作 |
| --- | --- |
| L | 开始或停止收听所选 QQ 进程树 |
| P | 播放一次固定测试音，默认 800 ms、音量 0.12 |
| W | 播放启动时 `--wav "固定回复.wav"` 指定的 PCM WAV |
| X | 停止当前输出；显示本地取消与清理耗时 |
| M | 静音或解除；静音会停止当前输出，解除后不会续播 |
| S | 查看采集状态、输出状态、电平和错误 |
| Q / Ctrl+C | 停止并退出 |

`X` 的本地耗时不包含 QQ 和远端设备缓冲，不能当作群友实际听到的停止延迟。电平是本次收听累计值；每次重新开始收听会重置。

## 音频路由和验收

完整步骤见 [Files/audio-routing.md](Files/audio-routing.md)。核心连接为：

```text
群友声音 → 桌面 QQ 的播放流 → 按 QQ 进程树采集 → 本地 ASR → 对话控制 → DeepSeek（仅文字/明确关联图片）
固定音/WAV/本地 Huihui 合成 → CABLE Input（播放端）→ CABLE Output（录音端）→ QQ 麦克风 → 群友
```

QQ 的扬声器选择 USB 耳机，麦克风选择 **CABLE Output**；当前 QQ 若没有内置设备选择入口，可在 Windows 音量合成器中设置 QQ 的应用输入设备。系统默认设备保持原样，关闭 CABLE Output 的“侦听此设备”；所有参与者首轮戴耳机。主程序的接收路径只采集 QQ 进程树，不回放采集输入；独立虚拟线缆诊断会另外采集 CABLE Output 验证本地通路。

Windows 应用输入偏好可能由同一可执行路径的多个 QQ 实例共享，不能按界面中的一个进程或账号推定隔离。早期调整曾使两个 QQ 音频进程都使用 CABLE Output；把偏好恢复成“默认”后，已经创建的活动流仍可能留在旧设备。设置或恢复后须重新建立通话音频流，并核对实际活动输入端点。当前用独立设备作对端，操作和恢复步骤见 [Files/audio-routing.md](Files/audio-routing.md)。

Windows 按进程捕获可以排除其他进程的声音，但 **QQ 自己的提示音、其他 QQ 窗口的声音以及远端回传的机器人声音仍可能进入 QQ 音轨**。请在 QQ 内关闭无关提示音，首轮只保留一场通话。程序不会退回系统全局采集来掩盖选择错误。

这些自动化测试不打开音频硬件。真实固定音核心通路与固定中文 WAV 可懂度另已通过受控观测；真人唤醒、自动问答、有效插话、多人/外放回音、重复与长时间运行、手动停止/静音的远端表现、实际停止延迟及设备故障恢复仍需单独验证。Windows 原生设备激活/初始化如果卡死，不能保证在该调用返回前完成取消；清理超时会明确报“资源尚未确认释放”并锁定相关会话/语音实例，需退出程序检查设备。

路线依据、NapCat 部署门槛与 DeepSeek 费用来源见 [Files/feasibility.md](Files/feasibility.md)。本机中文 14M int8 ASR 模型约 29.54 MiB，加载约 0.94～1.52 秒；支持 44.1/48 kHz 输入并在识别器内部转为 16 kHz。Huihui 短句内存合成实测约 0.578 秒，取消约 9.87ms；这些分段耗时不是“说完到群友首音”或远端停止延迟。目前没有机器人执行电脑命令或任意文件操作的入口；`--wav` 只读取用户明确指定的开发测试音频。

## 故障处理与恢复

- **找不到 CABLE 设备**：驱动未安装或尚未重启；不要把物理麦克风误当虚拟麦克风。安装方式和恢复见路由说明。
- **QQ 进程不存在/不是根进程**：QQ 重启或选择了子进程。重新运行 `qq`，配置目标根 PID。
- **群友讲话时无电平**：确认自己能在耳机听见对方、选择的 QQ 实例正确、未被 QQ 内静音；再检查通话是否使用独立辅助进程。保留失败证据后再调整采集目标，不自动全局采集。
- **电平有变化但群友听不到测试音**：检查程序输出为 CABLE Input、QQ 实际活动输入为 CABLE Output、QQ 通话未静音。只看 Windows 应用输入偏好或本地 completed 不够；同机双 QQ 还可能共享路由。系统麦克风权限弹窗由用户处理。
- **有回声**：先全员戴耳机、关闭“侦听此设备”和软件监听；让其他人静音后单独播放，检查是否为远端外放回传。M 可立刻禁用后续输出。进程隔离不能消除已经由远端回传的声音。
- **拔掉设备后播放失败**：错误会显示在状态中；恢复设备后重新运行 `devices`，必要时退出并更新配置。不会偷偷改用系统默认扬声器。
- **采集底层超时**：本次会话不再重开采集；退出应用，检查设备/QQ。异常退出后再重新启动，不将未确认释放当作正常完成。
- **想恢复原使用方式**：退出工具，把 QQ 麦克风、扬声器及 Windows 中 QQ 的应用输入偏好恢复为各自记录的原值；重新建立通话音频流，必要时重启 QQ，并核对实际端点。只把偏好改回“默认”不保证已有流立刻切换。如不再需要 VB-CABLE，按安装器的 Remove Driver 卸载并重启。没有安装 QQ 插件，无需回滚 QQ 文件。
